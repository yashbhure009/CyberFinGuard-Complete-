# Live dashboard setup

Use Python 3.10 or later and Node.js with the dependencies in `requirements.txt` and `frontend/package.json`.

1. Set PostgreSQL connection variables in `.env`. Make ZAP and Nuclei available for website scanning; set `ZAP_URL`, `ZAP_API_KEY`, and `NUCLEI_PATH` where needed.
2. Install Python dependencies: `pip install -r requirements.txt`.
3. Initialize the schema: `python setup_db.py`. Do not insert sample records when using live dashboards.
4. Start the API: `python -m backend.live_api` (port 8000). If you previously used `python backend/api.py`, restart it so it loads the same live API routes.
5. In `frontend`, run `npm install` and `npm run dev` (port 3000).
6. Open the assessment and save the website URL; this starts the website scan immediately. Enter business/impact facts while it runs, then review auto-filled risk fields, enter MFA/WAF/EDR, and submit. The technical, risk, executive, and compliance pages query PostgreSQL.

The website scan starts as a background job from the submitted URL. It runs ZAP and Nuclei against that URL; Nmap, Wazuh, Prowler, and Keycloak are separate workflows and require no input for a website scan. DNS/IP resolution does not gate the website scan. `/api/scan/status` reports the current stage and findings count. Ingestors write findings to PostgreSQL as they complete, and technical, compliance, executive, and risk views refresh every five seconds. Views and `data/unified_findings/latest.json` use findings from the current target and scan start time, so older rows cannot appear as new scan results. `latest.json` is rewritten after each website scanner and the timestamped export is written at completion. `data/scan.log` contains scanner output for troubleshooting.

The scanner host must be able to reach private or Tailscale targets. Configure Nuclei with `NUCLEI_RATE_LIMIT`, `NUCLEI_CONCURRENCY`, `NUCLEI_REQUEST_TIMEOUT`, `NUCLEI_SCAN_TIMEOUT`, and `NUCLEI_MAX_HOST_ERROR` in `.env`. The default profile is bounded at 40 requests/sec, 15 concurrent requests, and 10 minutes; lower these values for fragile targets. If the host becomes unresponsive, the scan log reports a failure rather than treating zero matches as a clean result. Threat intelligence enriches CVEs found in the current scan only.

The frontend sends `/api` requests through the Next.js server to the local API on port 8000. This also works when the site is opened through a remote or Tailscale URL. Set `NEXT_PUBLIC_API_BASE_URL` only when the API has its own browser-reachable origin. Set `FRONTEND_ORIGIN` for a different frontend origin. Assessment configuration, including the Keycloak client secret, is stored in ignored `data/scan_config.json`; protect access to this file and the API host.

The active website URL is restored from the saved assessment configuration. The technical dashboard groups repeated scanner observations by source, title, and evidence URL; each row shows its source, last observation, evidence URL, and repeat count. Missing patch, MFA, WAF, and EDR telemetry is unknown, not a failed control.

The assessment progress starts at 0% on each page load; the saved target remains available. Business impact values are collected once in the business context step and stored in `impact_context` (with asset value and data type in `assets`, backup state in `asset_controls`). The risk step appears after a completed scan. Its eight scanner-derived likelihood fields are read-only, with observed/inferred provenance. Only MFA/WAF/EDR are editable. Scanner CVSS/EPSS values take priority; missing scores use severity-derived model inputs and are labeled as estimates on the technical chart.

On submission, the raw combined intake is committed to `risk_assessment_inputs.raw_input` before it is read back and transformed into the exact nested JSON in `backend/risk_model_input_schema.json`. The model payload is stored in `model_payload`, then sent to `https://cyberfinguard-risk-api.onrender.com/risk`. Responses are stored in `model_result` and the existing `risk_scores` table. If the model call fails, raw intake and payload remain in PostgreSQL with a failed status; dashboards show pending rather than a fabricated score. The risk and executive views read the latest completed assessment from PostgreSQL. The Risk Quantification Workspace shows the model's finding breakdown and offers a PDF summary generated by the backend without an added PDF dependency.

The JSON contract matches the currently deployed hosted API. If a separate `risk_engine/` service replaces that API, its owner must sign off on the contract before the integration is switched.

No cloud or Keycloak credentials are sent to the model. The deployed API currently accepts `Public/Internal/Confidential`, `Financial/Credentials/Intellectual_Property/Operational`, and `GDPR/DPDPA/RBI/SEBI` for the respective impact enums. These differ from some example values in the supplied feature list. Missing threat actor or malware evidence uses the documented `Unknown`/`No` values; missing CVSS/EPSS uses severity estimates. The displayed ALE and 95th-percentile value are hosted model outputs combined across unique source/title issues with a 35% overlap weight. This combination is a planning assumption. Remediation costs and effectiveness are planning allowances, not vendor quotes or measured control outcomes. Optimization chooses the highest estimated annual avoided loss within the entered budget. The compliance view shows suggested framework references and marks framework status "Not assessed" until control evidence is reviewed; scanner mappings are not compliance scores. Cloud scanning currently uses Prowler credentials from the host environment; the cloud form records account context but does not provision credentials.

The assistant answers a small set of database summary questions. Its scenario view shows a stored ALE baseline when available and leaves the simulated result pending because the repository has no quantified scenario model. The browser profile is a local label, not account authentication; keep the API bound to localhost unless authentication and authorization are added.
